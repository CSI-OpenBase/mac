# 数据模型

CSI OpenBase 使用工作区外壳和四类不可变业务快照。JSON Schema 位于 `admin_app/resources/`，MySQL 表定义位于 `mysql-schema.sql`。

所有用户可见时间、导出 manifest 时间及 `<日期时间>` 目录名统一采用北京时间（UTC+08:00）。SQLite/MySQL 内部时间与规范化数据时间戳仍保存为 UTC，避免改变排序、比较和既有历史数据；页面读取时转换为北京时间。

## 工作区

`workspace.json` 只保存非敏感配置：工作区 slug、展示名、平台、可选主页 URL 和数据库名。MySQL 密码、Cookie 和浏览器会话不进入该文件。

## 账号画像

`account/profile-snapshots.jsonl` 保存账号在某个观测时间的聚合计数：粉丝、关注、获赞和作品数。相同平台和观测时间只能有一个快照。

## 受众画像

`account/audience-snapshots.jsonl` 将创作者中心展示的聚合分布规范化为 `dimension / segment / share`。例如年龄、性别或活跃时间段。这里只保存群体比例，不保存任何观众账号标识。

## 作品表现

`works/work-snapshots.jsonl` 保存作品在某个观测时间的播放、互动、留存、主页访问和涨粉数据。系统识别官方作品 ID、视频 ID、`item_id` 与 `aweme_id` 等常见表头；仅在导出文件缺少稳定 ID 时，才使用标题与发布时间生成合成 ID。同一作品多次导入会保留时间序列。

主页同步还会在 `works/discovery/` 保存发现批次，并在 `works/videos/douyin/<video_id>/metadata/` 保存逐视频观测记录。首页视频档案以北京时间显示记录中的作品发布时间；旧 SQLite 索引没有该字段时，从档案指向的最新元数据快照回读。独立的 `/video-archive` 页面从同一最新元数据快照列出封面、作品身份、完整描述、发布时间、分组、播放/点赞/评论/收藏/分享指标、首次发现、最近同步、观测时间和采集来源；本地封面接口只允许读取对应视频档案目录内的文件。记录中的 `visible_metrics.comment_count` 是同步时主页或平台响应可见的评论总数。首页“获取最新评论”也只读取单个视频的平台评论总数，并在 SQLite 中保存最后获取时间以及与上一次可见总数的差值；该操作不请求评论列表、不创建评论目录，也不写入评论正文。

视频档案分组保存在本地 SQLite 的 `archive_groups` 与 `archive_video_groups`。主页响应明确提供抖音栏目（合集）时，同步任务以平台栏目 ID 作为稳定来源创建同名平台分组，并更新作品归属；只有完整同步结束后才清理已经没有作品的平台分组。用户创建的本地分组使用独立 ID，可重命名、删除并批量调整作品归属，后续平台同步不会覆盖这些关系。删除用户分组只删除归组关系，不删除作品档案。

这里的“视频档案分组”只用于本地整理，与 `comments/collection-targets.json` 中用于评论采集进度的合集清单是两个独立边界，不应互相推导或覆盖。

平台可见总数与用户手动导出的匿名评论记录数分开维护。`visible_comment_count`、`last_comment_count_at` 和 `comment_count_delta` 描述最后一次平台计数观测；`comment_count` 和 `last_comment_export_at` 只描述最近一次“导出评论”的结果。平台审核或删除可能使变化量为负数。

## 评论

工作区级 `comments/comments.jsonl` 保存导入评论的最新状态，`comments/batches/` 保存历史导入批次。逐视频本地档案还在 `works/videos/douyin/<video_id>/comments/comments.jsonl` 保存跨手动批次合并的最新状态。评论仅区分观众和创作者角色，不保存昵称、用户 ID、头像或属地。MySQL 同时保留最新态和不可变快照。

本地归档模式始终将每次评论采集的完整快照保存到 `works/videos/douyin/<video_id>/comments/<日期时间>/`，并写入 `manifest.json` 记录模式、基线、完整性、快照文件、交付文件和新增、更新、未变化、关系上下文、当前未观察到的数量。“导出评论”以 `platform + comment_id` 为稳定键，与逐视频最新状态比较；`collected_at` 和 `collection_batch` 的自然变化不会触发重复导出，正文、点赞数、回复数或关系等字段变化会作为更新再次导出。新增或更新的回复会自动附带其父评论和根评论，使增量 JSONL 仍可独立通过关系校验；这些附带记录单独计入 `context_count`，不计作新增或更新。首次运行没有基线时，全部可访问评论都属于新增。“完整重新同步”交付本次完整快照，但同样更新本地最新状态。

完整或部分完成的批次可以推进逐视频最新状态；阻断批次只保留审计文件，不能成为后续基线。当前快照没有观察到的历史评论不会自动删除，因为评论可能被平台隐藏、审核或临时不可访问；部分批次尤其不能作为删除依据。用户可在“设置”中指定评论导出目录；设置后，增量模式的新增与变更 JSONL 或完整同步模式的完整 JSONL 会原子复制到 `<设置目录>/<video_id>/<日期时间>/`。外部副本由用户管理，不作为本地索引的数据源，也不随“清空数据”删除。设置保存在 SQLite 的 `local_preferences` 元数据中，“清空全部数据”仍会保留；留空设置即可停止生成外部副本。

页面驱动按人类平均操作速度的 130% 采集。基准平均耗时按打开评论页 3 秒、展开后渲染 650ms、滚动扫读 1.3 秒、阅读基础 1.3 秒加每条新评论 350ms、单次阅读最高 6.5 秒计算；以 1.3 倍速度执行后，对应等待约为 2.31 秒、500ms、1 秒、基础 1 秒加每条 269ms、最高 5 秒。每次扫描最多检查 64 个回复入口但只点击一个，形成“点击、阅读、点击、阅读”的交替过程；当前视区没有可展开回复时才滚动。采集一旦满足严格完整性条件即结束；默认 600 秒仅是大量回复场景的保护上限，不是固定等待时间。节奏调整不改变一级评论、回复分页、父子关系或平台汇总数的完整性判定。

评论完整性按结构和平台汇总数分别校验。一级评论声明的回复数、分页结束状态及父子关系保持严格校验；抖音汇总总数可能因隐藏、审核、删除、缓存或采集期间变化而偏离当前可访问记录数。根评论分页与所有回复分页均已结束、可见根评论的回复声明逐一满足且不存在结构错误时，任务按当前可访问范围标记为完成；超过 5% 的平台总数差异会保留提示，说明可能存在已删除、审核隐藏或暂不可见评论，但不再单独降级为 `partial`。回复分页已结束但实际捕获数少于声明数时仍标记为 `partial`，只有差异来自同一评论串中父回复不可用的孤儿评论才视为完成；分页未完成或存在阻断性关系错误时仍标记为 `blocked`。回复实际捕获数高于根评论的过期声明同样不属于数据缺失。程序会级联排除孤儿回复，并提示父评论可能已删除及跳过数量。

评论采集目标位于 `comments/collection-targets.json`。后台既可导入这份完整 manifest，也接受以下简化 JSON；直接作品 URL 中的数字 ID 会自动提取，未分组作品归入“全部作品”：

```json
{
  "videos": [
    {
      "video_url": "https://www.douyin.com/video/1234567890123456789",
      "title": "作品标题"
    }
  ]
}
```

目标导入采用完整清单替换语义。服务端补齐合集、集号、计数和时间戳，严格校验后与 `collection-progress.json` 原子更新；仍在新清单中的视频保留原采集状态，移除目标不会删除已有评论。
已有工作区的 `scope_id` 不允许通过 Web 上传改变；数据库同步也会清理同一平台上被新清单取代的旧 scope 状态。

## 分析输出

`reports/` 保存账号基础分析和评论分析。基础分析目前包括作品分布、互动率、主页访问率、涨粉转化、评论问题需求和数据覆盖提示。所有比率都能由本地快照直接复算，不应解释为平台因果关系或收益承诺。

## 本地数据清理

本地页面提供三个白名单清理范围。“平台导出的原始数据”删除 `exports/` 及对应导出任务记录；“用户评论数据”删除逐视频内部 `comments/` 目录、评论导出任务记录和已导出数量，但保留视频档案、分组、评论数刷新任务、最后一次平台评论总数、变化量、评论导出目录设置及外部副本；“全部数据”删除 `exports/`、`works/` 以及 SQLite 中的账号、视频、分组和任务索引，但同样保留评论导出目录设置及外部副本。

Web 清理功能始终保留用户选择的工作目录、工作目录根部的其他文件、运行日志及浏览器登录授权；`exports/` 与 `works/` 是程序托管目录，清空相应范围时会删除其中全部内容。清空全部数据后，用户需要重新校验创作者账号。存在等待中或运行中的任务时，清理请求会被拒绝；程序也会拒绝清理包含链接、目录联接点、挂载点或与浏览器授权目录重叠的数据路径。

清理多个目录时，程序会先将全部目标移入工作目录内的隔离区，再更新 SQLite 索引。准备或数据库更新失败时会恢复原目录；若文件占用导致提交后的物理删除未完成，页面会提示关闭占用程序后再次清理。
