# CSI OpenBase 架构

## 产品分层

```text
抖音创作者中心 / 账号公开互动
                ↓
CSI OpenBase（开源、本地优先）
  工作区、采集、快照、基础统计、标准导出
                ↓ 创作者主动选择并授权数据
CSI（商业深度服务）
  内容结构、增长归因、行业基准、深度报告、行动建议
```

CSI OpenBase 沉淀创作者数据并提供可解释的基础洞察；CSI 在用户主动选择并授权的数据之上提供深度诊断与行动建议。开源端的结果必须能由输入数据和公开规则复算，不复刻 CSI 的商业评分模型。

## 工作区隔离

当前部署模型是“本地单操作者，一次运行一个活跃工作区”：

```text
项目目录/var/                 # 默认；除 README.md 外不参与 Git 提交
  README.md
  active-workspace
  workspaces/
    <slug>/
      workspace.json
      account/
      works/
      comments/
      reports/
  sessions/
    <slug>/                  # 敏感浏览器登录态
```

每个工作区使用独立数据库。数据库内的一行 `workspace_identity` 会在启动时绑定并校验工作区，任务在创建和执行期间只访问当前工作区的数据根；浏览器登录态不会跨工作区复用。这个边界比在每条查询中依赖可遗漏的账号过滤条件更适合本地开源版本。

浏览器登录态与业务数据使用同一个 `var` 根目录，但分别位于 `sessions/<slug>` 和 `workspaces/<slug>`，不会跨工作区复用。登录态可能包含 Cookie，必须视为敏感凭据；`var` 除说明文件外全部被 Git 忽略，也不应放入公开源码包。CLI 激活工作区只影响下一次进程启动；运行中的后台不会热切换账号。

默认 `CSI_OPENBASE_HOME` 是项目内的 `var`。自定义目录可以位于仓库之外；若位于仓库内，也只能使用 `var` 或其子目录，避免运行数据混入源码。CLI 数据库导入只接受当前工作区目录内的规范评论、目标和进度文件，避免手工路径误选导致跨账号写入。

若未来提供共享在线服务，必须另行增加用户认证、工作区成员关系、资源授权和数据库租户键。当前回环地址后台不能直接作为多租户服务部署。

## 适配器边界

抖音是当前第一个平台适配器。平台响应解析、视频 URL 校验等逻辑可以保留在抖音采集器内；工作区、快照契约、分析输入和报告不应写死某个账号、合集或内容领域。
